# 공유 이미지 품질 개선 — 배포 전 검증

## 구현

- html-to-image 1.11.13 고정 설치, 두 고정 카드에서 html2canvas와 비교 후 **로컬 기본**으로 선택.
- 기존 html2canvas는 비교용으로 남김. 캡처 실패 때 자동 폴백하지 않음(깨진 이미지를 조용히 저장하지 않기 위함).
- 실제 공유용 ShareCard/CourseShareCard를 재사용하는 개발 전용 `/auth/share-qa`.
  운영 NODE_ENV에서는 404. auth 아래 경로는 기존 proxy 통과 규칙을 이용하며 인증/권한 코드는 변경하지 않음.
- 사진을 fetch+decode하여 복제 카드에 data URL로 내장. HTTP/CORS/디코딩 실패 시 저장 중단·오류·재시도.
  사진 주소가 애초에 없는 장소는 정상 이모지 placeholder. 사진이 있는데 실패한 경우와 구별.
- 긴 공백 없는 이름 줄바꿈, 여러 줄 설명 보존. 고정 폭 400px, 전체 높이 PNG.
- 모바일 메모리 상한 2배/12MP. 과도한 길이(8000px 초과)는 안내 후 중단.
- 미리보기/다운로드/공유는 동일 Blob을 사용. 모달 닫기/재열기 중 이전 비동기 결과가 덮어쓰지 않도록 세대 번호 검사.
- 사진/글꼴/캡처 시간 제한. 아직 지원하지 않는 서버 캡처 API나 외부 서비스로 사진을 전송하지 않음.

## 고정 기준 v1

`src/components/ShareCaptureQA.tsx`의 장소 1개/코스 1개만 사용. 실제 DB에 테스트 데이터를 넣지 않음.

- 장소: 긴 한글+공백 없는 제목, 3줄 설명, 별점, 카테고리, 워터마크.
- 코스: 12개 장소(두 자리 번호 포함), 긴 이름, 일부 좌표 없음, 2줄 소개.
- 사진 있음/없음/깨진 URL 세 모드. 사진 있음은 네트워크에 의존하지 않는 SVG 도형 fixture.
  실제 Supabase 사진 URL의 CORS/디코딩 및 실제 휴대폰 사진 케이스는 별도 검증 필요.

## 2026-09-01 확인 결과

| 검사 | 결과 |
|---|---|
| 데스크톱 Chromium 양쪽 엔진 PNG 생성 | 장소 800×1288 / 코스 800×1602 |

| 미리보기/실제 다운로드 바이트 | 장소 후보 SHA-256 일치: 22acdecf75d6ed0f74920ac9c1adad1582a37b4ee64d26fa9c7c3d116dd5d03f |
| 390×844 Chromium 뷰포트 | 모달/미리보기/저장 버튼 표시 확인 (실제 iPhone 아님) |
| 타입 검사/변경 파일 ESLint | 통과 |
| iPhone Safari / Android Chrome 실기기 | **미검증 — 완료 기준 미충족** |
| 공유 대상 앱의 저장/재인코딩, 느린 외부 폰트/CORS | 미검증 |

브라우저 다운로드 이벤트는 도구가 시간 초과했으나 파일은 실제 Downloads에 생성됨.
이를 직접 읽어 SHA-256 및 원본 PNG 시각 검증. 전체 페이지 스크린샷은 stitching 오류가 있어
이미지 판단은 저장된 원본 PNG 기준으로 진행함.

## 사용자 실기기 확인

개발 서버의 `/auth/share-qa`를 열어 사진 모드별 두 엔진을 비교.
모바일은 같은 Wi-Fi에서 Mac의 개발 서버 주소 이용(현재 서버 3000).
HTTP LAN에서는 Web Share/해시가 제한될 수 있으므로 PNG 다운로드 비교부터 수행.
실제 OS 공유 시트까지 검증하려면 HTTPS 테스트 환경이 필요하며 **배포는 별도 승인**.

1. iPhone Safari와 Android Chrome 각각 기기/OS/브라우저 버전 기록.
2. 사진 있음/없음에서 번호 1·10·12 및 태그 중앙 정렬, 마지막 문장/워터마크 확인.
3. 다운로드 파일과 화면 미리보기 비교. 메시지 앱에 공유한 뒤 재압축되는 것은 별도 구분.
4. 사진 실패에서 파일이 생성되지 않는지, 재시도/모달 빠른 닫기·재열기 확인.
5. 한 기기라도 누락/잘림/흰 사진이 있으면 기본 교체를 운영에 배포하지 말 것.

## 서버 실제 브라우저 방식 판단

실제 모바일에서 후보 엔진 문제가 재현되면 다음 단계로 검토한다. 지금은 서버 캡처 미구현.

- 인증된 요청은 장소/코스 ID만 받기. 서버에서 현재 사용자/같은 커플 권한 검사 후 데이터 읽기.
- 공유 전용 카드만 렌더, 폰트/사진 로딩 완료 및 실패 검사 후 Chromium으로 PNG 생성.
- 사용자 임의 URL/HTML을 받지 않기(SSRF/스크립트 실행 방지), 사진 origin 허용목록·요청 시간/크기/동시성 제한.
- 개인 PNG는 공개 캐시에 두지 않고 인증 응답 또는 짧은 수명의 접근 링크 사용.
- 장점: 번호/글꼴 렌더가 기기별 캡처 엔진에 덜 의존. 비용: 브라우저 실행 시간/메모리/콜드스타트 및
  개인정보 처리 경로 추가. 서버 렌더도 결과 PNG를 미리보기·저장에 동일하게 사용해야 함.

참고: https://github.com/bubkoo/html-to-image (API와 이미지 내장 방식). 실기기 통과를 라이브러리 문서만으로 판단하지 않음.
